# Pi Aerial

**Видеозаставка с часами для Raspberry Pi.** Превращает HDMI-экран в атмосферную видеопанель с календарём, прогнозом погоды и фоновыми роликами. Управляется из браузера в локальной сети.

*Ambient video clock & screensaver for Raspberry Pi.*

> **Разработка / Development:** весь исходный код Pi Aerial написан **ChatGPT (OpenAI)**.  
> **All source code was written by ChatGPT (OpenAI)**.

## Возможности

- **Видео:** Apple Aerial, NASA Image and Video Library, Robin Fourcade (AerialShots) и собственные файлы. Источники включаются и выключаются отдельно.
- **Подготовка под Pi:** последовательная загрузка, преобразование в H.264/MP4 до 1080p/30 fps и локальный кеш с паузой при заполнении, без удаления готовых роликов. Производительность зависит от модели Raspberry Pi.
- **Экран:** крупные часы, дата, календарь, текущая погода и прогноз на семь дней; затемнение ночью, подписи и описания роликов.
- **Визуальный редактор OSD:** во вкладке «Расположение OSD» можно выбрать один постоянный макет или два чередующихся при каждом следующем видео. Каждый из двух макетов настраивается отдельно: часы, погода, календарь и подписи перетаскиваются мышью или касанием, масштабируются за угол или ползунком. Для каждого блока в каждом макете отдельно задаются шрифт (из встроенного списка) и цвет текста; цвет и шрифт можно вернуть к значениям по умолчанию. Полный список установленных на Raspberry Pi шрифтов автоматически запрашивается через `fontconfig` (`fc-list`) и обновляется кнопкой в админке. Старые варианты выбора остаются для совместимости; отсутствие шрифта не ломает сохранённые настройки. Дополнительные шрифты из интернета не загружаются. В браузере на другом устройстве предпросмотр семейства шрифта может отличаться от HDMI-экрана малинки. В редакторе доступна отключаемая сетка 32×18: при включении блоки прилипают к ближайшим линиям при перетаскивании и перемещении стрелками; без неё можно выставлять координаты свободно. Сетка не отображается на заставке и её включение не меняет сохранённые позиции. Сброс возвращает оба макета к заводским позициям и включает стандартное чередование. Предпросмотр не декодирует видео; настройки применяются к экрану после сохранения, обычно в течение 30 секунд.
- **Веб-панель:** управление источниками, просмотр и удаление подготовленных видео, статус загрузки и перекодирования, настройка оформления и модулей.
- **Библиотека и ссылки:** вкладка «Библиотека» хранит список готовых роликов; в поле URL можно вставить ссылку на YouTube (watch, shorts, live, youtu.be) и показать ролик один раз на экране без OSD, со звуком, с прерыванием текущей заставки и возможностью остановки. После окончания или ошибки обычная заставка возвращается. Поддержка других хостингов добавляется в реестр `app/video_sources/`. Для YouTube используется официальный IFrame Player API без скачивания или кеширования. Страница заставки передаёт только origin через HTTP `Referer` (`strict-origin-when-cross-origin`), как требует YouTube; иначе плеер возвращает ошибку 153. API и медиа по-прежнему используют `no-referrer`. Также поддерживается **VK Видео**: ссылки `https://vkvideo.ru/video-123_456`, `vk.com`/`vk.ru` (включая `?z=video...`) и ссылки `video_ext.php?oid=...&id=...&hash=...` из команды «Поделиться → Код для встраивания». VK воспроизводится через официальный iframe и `VK.VideoPlayer`: поддерживается отслеживание завершения и ошибки, ручная остановка, звук, автоматический возврат к заставке. Система запрашивает `hd=4` (Full HD / 1080p), однако адаптивный плеер может выбрать другое качество. Для некоторых приватных роликов ключ `hash` обязателен; ограничения доступа/рекламы устанавливает VK. Ни YouTube, ни VK не гарантируют строгий потолок 1080p через встроенный плеер.
**Камера и микрофон:** экран заставки не запрашивает доступ к устройствам записи. Для `/` сервер отправляет `Permissions-Policy: camera=(), microphone=()`, а при новой установке kiosk Chromium запускается с `--deny-permission-prompts`, автоматически отклоняя всплывающие запросы без их разрешения. При обновлении существующей установки `~/pi-aerial/kiosk.sh` сохраняется отдельно от ядра. Чтобы распространить параметр и на уже установленный Chromium, один раз выполните `sed -i 's/--autoplay-policy=no-user-gesture-required/--deny-permission-prompts --autoplay-policy=no-user-gesture-required/' ~/pi-aerial/kiosk.sh` и перезапустите kiosk Chromium (например, перезагрузите Raspberry Pi). Не повторяйте `sed` после того, как параметр уже добавлен.

- **Обновления:** установка по кнопке или опциональное автообновление из GitHub с настраиваемым интервалом (по умолчанию 60 минут); ожидание завершения видео и автоматический откат при неудачном запуске.

**Требования:** Raspberry Pi с поддержкой Raspberry Pi OS **64-bit Desktop** (графическая среда `labwc` и Chromium), HDMI-дисплей, доступ в сеть для установки и онлайн-источников. **Реально тестировалось на Raspberry Pi 4.** Видеозаставка и часы могут работать с уже подготовленными локальными файлами без интернета.

### Совместимость с Raspberry Pi

| Модель | Статус |
| --- | --- |
| **Raspberry Pi 4 Model B** | **Тестировалась** |
| Raspberry Pi 5, 400, 500, 500+ | **Предположительно совместимы**, не тестировались |
| Compute Module 4, 4S, 5 | **Предположительно совместимы**, нужна плата-носитель с видеовыходом и подходящая Desktop-система |
| Raspberry Pi 3B, 3B+, Compute Module 3/3+ | **Экспериментально**: возможен запуск, но Chromium и конвертация видео могут работать медленно |
| Raspberry Pi 3A+, Zero 2 W | **Экспериментально, не рекомендуется для постоянного видеопоказа**: 512 МБ оперативной памяти сильно ограничивают работу Chromium |
| Raspberry Pi 1, Pi 2, Zero / Zero W первого поколения | **Не поддерживаются текущей инструкцией**: требуется 64-битная Desktop-система |

Это **прогноз совместимости по архитектуре и требованиям Raspberry Pi OS**, а не подтверждённые испытания. Даже на моделях с 64-битной ОС производительность декодирования H.264, интерфейса Chromium и фонового `ffmpeg` зависит от объёма памяти и железа. Для комфортной работы разумно ориентироваться на **Pi 4 или более мощные модели с 2 ГБ ОЗУ и выше**.

[Официальный список моделей, поддерживающих Raspberry Pi OS (64-bit)](https://www.raspberrypi.com/software/raspberry-pi-desktop/).


> **Права на видео:** ролики Apple, NASA и Robin Fourcade не входят в репозиторий и релизы. Лицензия MIT распространяется только на код. Сведения об условиях использования сторонних материалов см. в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## 1. Установка и первый запуск

**Шаг 0. Установите Raspberry Pi OS.** Воспользуйтесь [официальной инструкцией Raspberry Pi по установке ОС через Raspberry Pi Imager](https://www.raspberrypi.com/documentation/computers/getting-started.html#install-using-imager). Сам [Raspberry Pi Imager можно скачать здесь](https://www.raspberrypi.com/software/).

В Imager выберите свою модель платы и **Raspberry Pi OS (64-bit) с графическим рабочим столом (Desktop)**, а **не Lite**. Запишите систему на карту памяти или другой поддерживаемый накопитель, настройте пользователя, сеть и при необходимости автовход в рабочий стол. После первой загрузки ОС и подключения к сети откройте терминал Raspberry Pi и выполните:

~~~bash
sudo apt update
sudo apt install -y git
git clone https://github.com/ouchZZZ/Pi-Aerial.git "$HOME/Pi-Aerial"
cd "$HOME/Pi-Aerial"
bash install.sh
sudo raspi-config
~~~

Клонирование и обновления из публичного GitHub выполняются по **HTTPS без токена и SSH deploy key**. Существующие установки через read-only SSH deploy key продолжают работать.

В `raspi-config` включите **Desktop Autologin**, если он не был установлен через Imager. Отключите Screen Blanking (гашение экрана) в настройках рабочего стола Raspberry Pi OS. Перезагрузите:

```bash
sudo reboot
```

**Системные зависимости установит сам `install.sh`.** Перед созданием окружения он выполняет `apt-get update` и устанавливает/обновляет **только** закреплённый набор пакетов: `ca-certificates chromium curl ffmpeg git labwc openssh-client python3 python3-pip python3-venv sudo tzdata`. Полное `apt upgrade` всей ОС не выполняется. При первом запуске потребуется пароль `sudo` (обычная установка ПО).

Для обновлений через веб установщик дополнительно размещает root-owned помощник по пути `/usr/local/libexec/pi-aerial/system_deps` и узкое правило `/etc/sudoers.d/pi-aerial-system-deps`. Веб-обновление вправе вызвать **только** его команду `--ensure`: проверить и при необходимости установить отсутствующие пакеты из встроенного белого списка, без обновления всего дистрибутива и без передачи произвольных команд. Python-пакеты ставятся отдельно в `.venv` нового релиза. Если установку зависимостей не удалось завершить, новая версия не активируется.

Установщик спросит пароль веб-панели длиной не менее 12 символов и развернёт:

```text
~/pi-aerial/
├── current -> releases/<версия>-g<commit>/
├── releases/<release>/.venv/       # отдельные Python-зависимости для каждого выпуска
├── data/
│   ├── videos/                     # ролики, загруженные пользователем
│   ├── online_cache/               # готовые онлайн-видео MP4
│   ├── online_processed.json       # журнал обработанных роликов
│   ├── modules/                    # модули, предыдущие версии
│   ├── github.json                 # HTTPS-источник или старый SSH deploy key
│   ├── settings.json
│   ├── admin_auth.json             # соль и хеш пароля
│   └── pending_update.json        # временный запрос обновления
├── update_helper.py               # независимый помощник обновлений
└── kiosk.sh                        # Chromium в полноэкранном режиме
```

Экран запустится автоматически на HDMI. Веб-панель: **`http://IP-МАЛИНКИ:8080/admin`**. Непосредственный экран: `http://127.0.0.1:8080`.

**Безопасность:** веб-панель использует пароль + CSRF, но работает по обычному HTTP. Подключайте Pi только к доверенной локальной сети. Никогда не пробрасывайте порт `8080` в интернет. Если используется старый SSH deploy key, он должен быть read-only и предназначен только для Pi-Aerial.

## 2. Обновления из GitHub через веб

Во вкладке **Обновления** нажмите **Проверить GitHub**. Панель сравнивает SHA установленного кода и `main` официального репозитория. Если SHA отличается, доступна кнопка **Установить обновление**.

1. Ручной запрос или включённое автообновление ставит обновление в локальную очередь. Текущие скачивание, конвертация и принятая веб-загрузка завершаются; новые видео-задачи временно не запускаются. Установка начинается после их завершения, поэтому длительная конвертация не расходует таймаут установщика. Очередь видео продолжается после обновления или его неудачной попытки.
2. Отдельная user-служба `pi-aerial-updater.path` запускает установленный помощник.
3. Помощник скачивает ровно `ouchZZZ/Pi-Aerial`, ветка `main`, через публичный HTTPS или старый SSH read-only, сверяет SHA и создаёт каталог нового релиза.
4. Перед переключением root-owned помощник проверяет системные пакеты и автоматически доставляет отсутствующие. Если помощник ещё не установлен (старые установки 0.2.0), обновление продолжится без этой проверки, а в журнале появится предупреждение.
5. Новый релиз получает **собственное Python-окружение `.venv`**. Пакеты из `requirements.txt` устанавливаются заново при подготовке (включая повторную попытку после прерванного скачивания); зависимости старого релиза остаются нетронутыми.
6. Символическая ссылка `current` переключается атомарно. Перезапуск службы ставится в очередь systemd без блокирующего ожидания его завершения; до 150 секунд отдельно проверяются `/api/health`, версия и точный Git SHA. При неудаче служба возвращается к прежней версии, а восстановление старого процесса тоже проверяется через `/api/health`.
7. Если проверка успешна, обновляется и независимый helper (с сохранением предыдущего файла).

**Если прежний helper уже откатил обновление из-за `systemctl ... timed out after 35 seconds`:**
он хранится отдельно в `~/pi-aerial/update_helper.py`, поэтому новый код helper
не попадёт в него до успешного обновления. На такой установке сначала нужно
поправить независимый helper однократно (команда выполняется **от пользователя,
который установил Pi Aerial**, без `sudo`):

```bash
python3 - <<'PY'
from pathlib import Path
import shutil

p = Path.home() / 'pi-aerial' / 'update_helper.py'
src = p.read_text(encoding='utf-8')
old = "['systemctl', '--user', 'restart', 'pi-aerial.service'], check=True, timeout=35"
new = "['systemctl', '--user', 'restart', '--no-block', 'pi-aerial.service'], check=True, timeout=10"
old_wait = 'for _ in range(45):'
if src.count(old) != 1 or src.count(old_wait) != 1:
    raise SystemExit('Helper отличается от ожидаемого. Файл не изменён.')
shutil.copy2(p, p.with_name('update_helper.py.before-restart-fix'))
p.write_text(src.replace(old, new).replace(old_wait, 'for _ in range(150):'), encoding='utf-8')
print('Helper исправлен; предыдущий файл сохранён.')
PY
```

После этого повторите обновление из веб-панели. Новый релиз установит уже
полноценный helper с проверкой успешного отката. Сам откат сохраняет кеш
и настройки.

Настройки, видеозаписи, пароль и данные модулей лежат вне каталогов выпуска и **не удаляются при обновлениях**. По умолчанию изменения `main` устанавливаются по кнопке. В **Настройки → Автообновление** можно включить автоматическую проверку и установку, а рядом задать интервал проверки в минутах (целое число от 1, по умолчанию 60). Неудачный SHA автоматически повторно не устанавливается: доступен ручной повтор или следующая версия. Если `main` изменился между проверкой и скачиванием, установка отменяется; повторите проверку.

Обновляться можно даже без изменения `VERSION`: учитывается SHA коммита. Для читаемого номера версии при выпуске полезно повышать `VERSION` (`0.2.1` и т. д.). GitHub-обновления ограничены официальным репозиторием `ouchZZZ/Pi-Aerial`, веткой `main` и проверкой точного Git SHA. Для новых установок используется HTTPS, для старых SSH; это отдельный механизм от подписи ZIP.

*Automatic updates:* disabled by default. Enable in Settings and choose the check interval in minutes (positive integer, default 60) for the official GitHub main branch. Active video downloads/conversions finish before installation; queued media work resumes afterwards. Failed revisions require a manual retry or a newer commit.

**GitHub-токены для HTTPS-установки не нужны.** Существующий read-only SSH deploy key продолжит работать.

### Обновление старой установки 0.2.0

Если Pi Aerial уже был установлен **до** появления автоматических apt-зависимостей, достаточно один раз обновить исходники и повторно запустить установщик (видеотека и настройки останутся нетронутыми):

```bash
cd "$HOME/Pi-Aerial"
GIT_SSH_COMMAND="ssh -i $HOME/.ssh/pi_aerial_github -o IdentitiesOnly=yes -o BatchMode=yes" git pull --ff-only
bash install.sh
```

Это установит root-owned помощник. Дальнейшие GitHub-обновления ядра не потребуют ручных действий с `apt`. При расширении системного белого списка новыми пакетами потребуется снова запустить `install.sh`, чтобы доверенная копия помощника была обновлена.

## 3. Каталог модулей

В репозитории каждая папка `catalog/<id>/` является модулем с собственными `manifest.json` и `index.html`, например `catalog/hello-widget/`. В панели: **Модули → Показать каталог → Установить / обновить**. Выключить или откатить модуль можно в той же вкладке. Защита: допустимые имена, ограничение размеров, запрет символических ссылок и вложенных директорий, запуск виджета внутри изолированного iframe.

При установке из GitHub используется закреплённый репозиторий и проверка Git SHA (HTTPS или сохранённый SSH-режим). Отдельно остаётся возможность установки **локального подписанного ZIP**, для которой требуются публичные Ed25519 ключи в `~/pi-aerial/data/trusted_keys/` (см. `tools/make_signing_key.py` и `tools/sign_bundle.py`). Публичные ключи можно добавлять только локально; секретный ключ подписи храните вне Raspberry Pi.

## Модерация каталога и Internet Archive

Вместо автозагрузки всего каталога Pi-Aerial показывает **предложенные
ролики**. Выбранные галочкой видео отправляются в единую очередь
скачивания и конвертации. Снятие выбора отменяет активную загрузку,
удаляет готовый файл (разовый показ защищён от удаления на время сеанса)
и не даёт скачать его вновь до повторного выбора.

На первом запуске после обновления **все ранее готовые MP4 отмечаются
автоматически**. Состояние сохраняется отдельно в `data/online_selection.json`.
Журнал `online_processed.json` остаётся для авторства и описаний,
но больше не используется как запрет повторного скачивания.
Существующие ограничения кэша, 50% свободной квоты на ролик и одна
одновременная загрузка/конвертация остаются.

В библиотеке: поиск по названиям, описаниям, годам и тегам (включая
«Сибирь» → `Siberia`), галочки фильтра по включённым источникам,
массовый выбор и снятие выбора **только по результатам фильтрации**,
постепенный вывод длинных списков. Для готовых роликов сохранены
предпросмотр и **«Показать один раз без OSD»**. Вручную загруженные
файлы управляются отдельно: у них нет каталога для повторного скачивания.

Internet Archive имеет пять независимо включаемых тем: Природа, Города,
Исторические города, Космос и Таймлапсы. По умолчанию выключены.
Поиск использует `advancedsearch.php`, подробности `metadata/{identifier}`.
Кандидат появляется, только если метаданные содержат явную лицензию
CC0/CC BY/CC BY-SA/Public Domain Mark, измеренное или указанное в
файле разрешение не ниже **1920×1080**, примерно **16:9**, допустимый
размер и продолжительность. Это первичная проверка метаданных,
**без анализа кадров нейросетью** и без гарантии авторских прав
(указанная загрузившим лицом лицензия может быть ошибочной).
Каждый ролик пользователь дополнительно выбирает вручную.

## Видеотека с предпросмотром и описаниями (0.3.9)

Вкладка **Библиотека** показывает предложенные и подготовленные онлайн-ролики
Apple Aerial, NASA, Robin Fourcade и тематических каталогов Internet Archive,
а также отдельный раздел файлов, загруженных вручную.
Выбор роликов для загрузки управляется галочками.
В «Библиотеке» есть фильтр с несколькими галочками по включённым источникам:
Apple, NASA, Robin Fourcade и вручную загруженные файлы (если их показ включён).
По умолчанию выбраны все; можно оставить один, несколько или вернуть все
кнопкой «Все источники». Отключённые источники отсутствуют в фильтре,
их файлы не удаляются. Фильтр влияет только на отображение библиотеки,
не на загрузку, воспроизведение и историю. Отдельной кнопки скачивания в браузер нет; для воспроизведения браузер получает видео через HTTP.

**Старой разблокировки повторного скачивания больше нет.** Снятие галочки
отменяет задание и удаляет скачанный файл, повторная установка галочки
позволяет загрузить файл заново. История метаданных сохраняется независимо.

Система сохраняет доступные текстовые описания Apple/NASA/Robin/Archive в каталоге
вместе с названием и авторством. Описания успешно подготовленных роликов
дополнительно сохраняются в журнале `data/online_processed.json`, чтобы
после удаления MP4 карточка сохраняла данные. У старых роликов описание
появится только если оно имеется в актуальном каталоге; искусственный текст
не генерируется.

На экране заставки **описание выводится внизу рядом с источником**
и укорачивается до 220 символов. Когда описания нет, интерфейс остаётся
как раньше. Просмотр кеша защищён сессией администратора и не запускает
фоновую загрузку.

### Звук при показе видео

При обычном автоматическом воспроизведении заставки звук всегда выключен.
**«Готовые файлы → Просмотр»** в админке и **«Показать один раз без OSD»**
на экране заставки воспроизводят ролик со звуком, если аудиодорожка есть.
После окончания, остановки или ошибки разового показа экран возвращается
к беззвучной заставке. Это не настройка файла, а режим проигрывателя.

С этого обновления конвертер сохраняет первую аудиодорожку в AAC (стерео)
при наличии звука в исходнике. **Ранее перекодированные файлы остаются
беззвучными**, так как старая конвертация удаляла аудио. Для восстановления
звука потребуется повторно загрузить исходник (или снять и вернуть галочку нужного онлайн-ролика). Беззвучные
Apple/NASA-источники, разумеется, звука не приобретут. Штатный Chromium
запускается с разрешённым автовоспроизведением; на сторонних браузерах
воспроизведение со звуком может требовать взаимодействия пользователя.

## Прогресс загрузки и подготовки видео (0.3.6)

Во вкладке **Видео → Загрузка и обработка видео** показываются текущие фоновые
задачи онлайн-кеша и локальных загрузок. Админка запрашивает свежие данные
раз в 2 секунды, пока вкладка открыта:

- загрузка: сколько байт получено, полный размер, процент и текущая скорость;
- перекодирование/перепаковка: обработанная позиция видео, длительность,
  процент и скорость обработки по собственным сообщениям `ffmpeg`;
- ожидание общего конвертера, проверка файла, готовность или ошибка;
- несколько последних завершённых задач остаются видны до 10 минут.

Если HTTP-сервер не сообщает `Content-Length` или `ffprobe` не определяет
длительность, **процент неизвестен**. Показан доступный объём, этап и время
работы вместо придуманного числа. Скорость, когда данные не поступают,
переходит к нулю.

Прогресс доступен только после авторизации администратора через
`GET /api/admin/videos/progress`. API не возвращает внешние URL,
ключи API и пути к файлам. За пределами памяти процесса старые графики
не сохраняются, после перезапуска текущая задача начинается заново
или возвращается в сохраняемую локальную очередь. Выгрузка логов в
GitHub не добавлялась.

## Загруженные видео: автоматическая фоновая конвертация (0.3.5)

Любой ролик, загруженный через **Видео → Загрузить ролик**, ставится в
сохраняемую на microSD очередь, а не сразу в проигрыватель. Поддерживаются
MP4, M4V, MOV, WebM и MKV. Один обработчик подготавливает совместимый с Pi 4
H.264/MP4, не больше 1920×1080/30 fps, с AAC-аудиодорожкой при
её наличии в исходнике, с `+faststart`.
Совместимый H.264 перепаковывается без потери качества, остальные кодеки
перекодируются с низким приоритетом процесса и ограничением в два потока.

**Очередь единая с онлайн-видео на уровне конвертера:** одновременно
обрабатывается максимум один файл. Готовый MP4 появляется в плейлисте
только после проверки выходного файла. Исходник удаляется **только после
успешной публикации**; если конвертация не удалась, исходник сохраняется.
Лимит готового ручного видео 4 ГБ; оставляем не менее 5 ГБ свободно,
при загрузке требуется запас 9 ГБ и больше.

Админка показывает состояния **В очереди**, **Фоновая конвертация**,
**Не удалось обработать**, позволяет **Повторить** и **Удалить исходник**.
Статус обновляется раз в 10 секунд во вкладке «Видео». После перезапуска
прерванные задания продолжаются. Уже загруженные видео старых версий
**тоже автоматически попадут в очередь** и временно будут скрыты из
плейлиста, пока не пройдут проверку. После успеха исходный файл заменяется
на новый нормализованный MP4 в папке локальных видео.

Работает независимо от галочки «Загруженные файлы» и настроек онлайн-кеша.
Ошибки можно увидеть в логах: `journalctl --user -u pi-aerial -f`, строки
`[local-video]`. При отсутствии `ffmpeg` установите пакет
`sudo apt install -y ffmpeg`, затем повторите неудавшуюся задачу в админке.

## Фоновая подготовка видео (профиль, проверенный на Raspberry Pi 4)

Apple Aerial использует TAR-каталог **tvOS 26**. Сначала выбирается
1080p H.264, затем 1080p SDR HEVC; если Full HD недоступен, берётся
4K SDR. HDR используется только как последний резервный вариант.

Совместимые H.264/8-bit yuv420p до 1920×1080/30 fps, включая онлайн-ролики,
перепаковываются в MP4 с `+faststart` **без повторного сжатия видео**.
Несовместимые исходники перекодируются в H.264 с CRF 20, `superfast`,
ограничением 12 Мбит/с и масштабированием bicubic. Частота кадров
сохраняется, если она не превышает 30 fps; для более высокой частоты
устанавливается предел 30 fps. Процесс по-прежнему ограничен двумя потоками.
Ранее подготовленные ролики не затрагиваются и автоматически не
перекачиваются; для повторной подготовки можно снять блокировку
скачивания нужного ролика через админку и загрузить его заново.

Скачивание строго последовательное: новый онлайн-ролик начинает
скачиваться только после окончания конвертации предыдущего. Обработчик
использует nice -n 15 и максимум два потока ffmpeg. Исходный временный
файл удаляется после завершения обработки. Готовый MP4 появляется в
плейлисте только после проверки совместимости.
Общее время конвертации не ограничено. После 20 минут без продвижения
ffmpeg получает ещё 20 минут; если прогресса по-прежнему нет, задание
завершается с ошибкой. Рост времени видео, числа кадров или объёма результата
сбрасывает ожидание, в том числе после первого предупреждения.

Apple, Robin Fourcade и NASA постепенно готовят все уникальные ролики
из каталогов. Загрузка распределяется между включёнными источниками
по кругу: Robin → Apple → NASA, затем повтор. Следующий источник запоминается
при перезапуске. Одновременно обрабатывается только один ролик.
Общий кеш ограничен
настройкой (по умолчанию 12 ГБ), резерв свободного места составляет 5 ГБ.
Максимальный размер исходника и готового файла — 50% свободной квоты кеша
на момент запуска задания. При заполнении квоты **новые загрузки ставятся
на паузу без удаления готовых файлов**.
Также загрузки приостанавливаются, если на карте осталось слишком мало
места для временных файлов и безопасной конвертации. При увеличении
лимита или освобождении места очередь автоматически продолжится.
Верхняя граница настройки зависит от физической ёмкости карты минус
резерв 5 ГБ; прежний искусственный предел 64 ГБ убран.

Идентификаторы успешно подготовленных роликов сохраняются в
`data/online_processed.json`. Даже если кеш вручную очистят, эти
ролики не будут загружены повторно. В админке отображаются использованный
объём и причина остановки загрузки.

Обновление также обрабатывает собственные HTTP-ссылки NASA на
HTTPS-хосты NASA (без отключения проверки TLS) и имена с пробелами.
Старый кеш, созданный до проверки кодеков, автоматически
переподготавливается; несовместимые копии не используются.

Для установленной Raspberry Pi однократно требуется:

```bash
sudo apt install -y ffmpeg
ffprobe -version | head -n 1
```

Проверка подготовки:

```bash
journalctl --user -u pi-aerial --since "20 minutes ago" --no-pager | grep '\\[online\\]'
```

Если проблема аппаратного декодирования H.264 существует на конкретной
сборке Chromium, конверсия сама по себе её не решит. Тогда проверяйте
`video.canPlayType('video/mp4; codecs="avc1.42E01E"')` в консоли
Chromium. Ручные видео пользователя также проходят фоновую подготовку при необходимости, согласно разделу «Загруженные видео»; готовые ролики и настройки не удаляются при обновлениях.

## Источники видео (0.3.3)

В админке **Видео → Источники** рядом с Apple и NASA
есть отдельный переключатель **Загруженные файлы** (изначально включён).
Он определяет только появление вручную загруженных через веб-панель файлов
в плейлисте на экране. При выключении файлы остаются в видеотеке и доступны
для управления, а кеш онлайн-видео и настройки других источников не меняются.
При повторном включении они снова участвуют в воспроизведении.

Автоматическую и ручную выгрузку диагностических логов в GitHub в этой версии
**не добавляли**.

## Онлайн-видео и кеш (0.3.7)

Три независимых источника: **Apple Aerial**, **NASA Image & Video Library**
и **Robin Fourcade (AerialShots)** (все включены по умолчанию).
API-ключи не нужны. Pixabay и Pexels удалены из приложения;
старые настройки переключателей мигрируют автоматически.

Apple получает сведения из tvOS 26 TAR. Robin Fourcade загружается из
официального entries.json автора (18 видео: Норвегия, Французские Альпы,
Реюньон). Приоритет — 1080p H.264, затем другой 1080p, затем доступный 4K.
Все файлы проходят общий конвейер проверки и подготовки, одновременно
обрабатывается только один ролик. Каталоги Apple, NASA и Robin
обновляются раз в 6 часов, а кнопка в веб-панели позволяет повторить
проверку не чаще раза в минуту. При недоступности сети сохраняются
последние успешные метаданные и уже подготовленные MP4.

Онлайн-кеш по умолчанию составляет 12 ГБ, максимальный размер входного
и готового файла — половина оставшейся квоты кеша, резерв свободного места 5 ГБ. При заполнении кеша
скачивание автоматически приостанавливается, готовые видео остаются.
Очистка кеша не затрагивает локальные видео и журнал уже обработанных ID.

Apple использует источник видео, не предназначенный специально для
сторонних приложений, и его формат может измениться. NASA содержит
в том числе видеозаписи, не предназначенные для бесшовных заставок.

В браузере Chromium реальную поддержку каждого онлайн-видеопотока и аппаратное декодирование проверяйте на используемой модели Raspberry Pi; при невозможности воспроизведения сохраняется локальная заставка или переход к следующему доступному видео.

### Совместимость онлайн-роликов (0.3.7)

- **Apple Aerial:** выбор 1080p в приоритете; 4K берём только при
  отсутствии доступного 1080p. Совместимый H.264 перепаковывается в MP4
  без повторного сжатия, остальные видео приводятся к H.264 до 1080p/30 fps
  перед появлением в плейлисте.
- **NASA:** видео ищутся через Search API и проверенные asset-манифесты,
  включая нормализацию HTTP-ссылок на собственные HTTPS-хосты NASA.
- Chromium получает только прошедшие проверку файлы MP4 из локального
  кеша. Ошибки доступны в админке и журнале службы.

### Если Apple Aerial показывает 0 роликов и SSL CERTIFICATE_VERIFY_FAILED

Проверьте дату/время и доверенные сертификаты на Raspberry Pi. Веб-каталог использует
проверку TLS с системными корнями и публичным CA-набором `certifi`; проверки
сертификата или имени сервера **не отключаются**.

```bash
timedatectl status
sudo apt update
sudo apt install --reinstall -y ca-certificates
sudo update-ca-certificates --fresh
curl -Iv https://sylvan.apple.com/Aerials/2x/entries.json
```

Если `curl` по-прежнему пишет ошибку сертификата, проверьте, не подменяет ли
корпоративный прокси сертификаты HTTPS. Не используйте `curl -k` или Python
`verify=False` в качестве постоянного решения. Если сертификаты починились,
во вкладке **Видео** нажмите **Повторить проверку источников**. Apple, NASA и Robin
можно принудительно проверять не чаще раза в минуту.

## Язык, город и часовой пояс

- **Язык:** в верхней части админки выбирается **Русский / English**. Выбор сохраняется в конфигурации устройства и меняет язык админки, календаря, погоды и подписей заставки; уже сохранённые настройки не сбрасываются.
- **Город:** в «Настройки → Погода и часовой пояс» введите название и нажмите «Найти город», затем выберите результат. Геопоиск Open-Meteo (данные GeoNames) автоматически заполняет координаты и IANA-зону.
- **Карта:** кнопка «Показать карту» открывает интерактивную OpenStreetMap-карту. Щелчок определяет координаты, ближайший населённый пункт (Nominatim) и соответствующий часовой пояс (Open-Meteo). Для карты нужен интернет; вручную задать город и координаты можно всегда.
- **Часовой пояс:** выбирается из списка IANA, установленного на Raspberry Pi. После выбора не забудьте нажать «Сохранить настройки».

Картографические сервисы получают координаты только при открытии карты или выборе точки; поиск города отправляет текст запроса геокодеру. Использование сторонних сервисов требует соблюдения [их условий](THIRD_PARTY_NOTICES.md).

## 4. Видео, погода, диагностика

Добавляйте ролики через вкладку **Видео** веб-панели. Рекомендуется MP4 1080p H.264 для Chromium. По умолчанию без видео показывается анимированный фон. Погода приходит из Open-Meteo примерно раз в 25 минут, без постоянного интернета остаются часы и видеозаставки; устаревший погодный кэш помечается.

Для настройки погоды в панели доступны город, координаты и часовой пояс IANA. Новая установка по умолчанию использует **Москву**, координаты **55.7558, 37.6173**, `Europe/Moscow`; настройки уже установленного устройства сохраняются. Данные Open-Meteo (CC BY 4.0) отображаются с атрибуцией; приложение преобразует значения и коды в иконки и недельный прогноз. Raspberry Pi 4 без внешнего RTC нуждается в NTP после отключения питания.

```bash
systemctl --user status pi-aerial.service pi-aerial-updater.path
journalctl --user -u pi-aerial.service -n 100 --no-pager
journalctl --user -u pi-aerial-updater.service -n 100 --no-pager
hostname -I
```

Отладка видео: `pgrep -af chromium`. Если ОС без рабочего стола (Lite) или не используется `labwc`, установленный автозапуск Chromium не сработает: нужна Desktop-версия Raspberry Pi OS с автовходом.

## 5. Разработка и тесты

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
pytest -q
bash -n install.sh && bash -n tools/system_deps.sh
python -m compileall -q app tools
```

Локальный запуск: `PI_AERIAL_BASE="$PWD" PI_AERIAL_DATA_DIR="$PWD/data" python -m uvicorn app.main:app --reload --port 8080`. Для задания пароля локально: `PI_AERIAL_DATA_DIR="$PWD/data" PYTHONPATH="$PWD" python tools/set_password.py`.

GitHub Actions (`.github/workflows/tests.yml`) запускает тесты на push и pull request. Для дальнейшей разработки лучше использовать PR и проверять CI перед слиянием в `main`: эта ветка служит источником обновлений работающей заставки.

## Известные ограничения

- Pi 4 поддерживает аппаратное декодирование HEVC, но реальная плавность 4K видео в Chromium с часами не гарантирована; начните с 1080p H.264.
- Автоматический откат срабатывает при неудачном запуске/проверке сервера, но не при любой логической ошибке отображения.
- Для установки обновлений и получения погоды нужен доступ к сети. Видеотека, интерфейс и часы работают локально.
- Для публичного GitHub deploy key не нужен; поддержка существующих read-only SSH-установок сохранена.
- Автоматические тесты выполняются на ПК; проверка на реальном устройстве проводилась на Raspberry Pi 4. Перед развёртыванием 24/7 на любой модели проверьте воспроизведение видео, терморежим и стабильность HDMI.
