# Pi Aerial 0.2.1

Постоянная видеозаставка для **Raspberry Pi 4**: локальные ролики, большие часы, дата, погода Open-Meteo и веб-панель. Всё хранится **на microSD 128 ГБ**. Поддерживаются модульные виджеты, обновления ядра из GitHub и откат при ошибке запуска.

> MVP. На конкретной Raspberry Pi 4 аппаратное воспроизведение пока не проверено. Для стабильности начните с MP4 H.264 1080p/30 FPS без звука. Крупные видеоролики не входят в репозиторий.

## 1. Один раз: read-only доступ Raspberry Pi к приватному GitHub

Репозиторий: **[ouchZZZ/Pi-Aerial](https://github.com/ouchZZZ/Pi-Aerial)**. Он приватный, поэтому обычный `curl` без токена не работает. Вместо постоянного PAT создайте на самой малинке **уникальный SSH deploy key с правами только чтения**.

В Raspberry Pi Imager установите **Raspberry Pi OS 64-bit with desktop** и задайте пользователя, SSH, интернет и автовход в графический рабочий стол. Подключитесь к малинке по SSH или откройте терминал:

```bash
sudo apt update
sudo apt install -y git openssh-client
mkdir -p ~/.ssh && chmod 700 ~/.ssh
ssh-keygen -t ed25519 -f "$HOME/.ssh/pi_aerial_github" -N '' -C 'Pi-Aerial Raspberry Pi read-only'
chmod 600 ~/.ssh/pi_aerial_github
cat ~/.ssh/pi_aerial_github.pub
```

Скопируйте **только публичный ключ** (строка `ssh-ed25519 ...`) на GitHub в **[Pi-Aerial → Settings → Deploy keys](https://github.com/ouchZZZ/Pi-Aerial/settings/keys)** → **Add deploy key**. Название: `Raspberry Pi 4`; опцию **Allow write access не включать**. Не копируйте приватный `~/.ssh/pi_aerial_github` на GitHub и никому его не присылайте.

Первое подключение к `github.com` может запросить подтверждение SSH host key. Перед ответом сравните отпечаток с [официальными ключами GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints):

```bash
ssh -i "$HOME/.ssh/pi_aerial_github" -o IdentitiesOnly=yes -T git@github.com
```

Ответ об отсутствии shell-доступа от GitHub при успешной аутентификации ожидаем и не является ошибкой. Настоящие проблемы с ключом проявятся как `Permission denied (publickey)`.

## 2. Установить из GitHub

```bash
GIT_SSH_COMMAND="ssh -i $HOME/.ssh/pi_aerial_github -o IdentitiesOnly=yes -o BatchMode=yes" \
  git clone git@github.com:ouchZZZ/Pi-Aerial.git "$HOME/Pi-Aerial"
cd "$HOME/Pi-Aerial"
bash install.sh
sudo raspi-config
```

В `raspi-config` включите **Desktop Autologin**, если он не был установлен через Imager. Отключите Screen Blanking (гашение экрана) в настройках рабочего стола Raspberry Pi OS. Перезагрузите:

```bash
sudo reboot
```

**Системные зависимости установит сам `install.sh`.** Перед созданием окружения он выполняет `apt-get update` и устанавливает/обновляет **только** закреплённый набор пакетов: `ca-certificates chromium curl git labwc openssh-client python3 python3-pip python3-venv sudo tzdata`. Полное `apt upgrade` всей ОС не выполняется. При первом запуске потребуется пароль `sudo` (обычная установка ПО).

Для обновлений через веб установщик дополнительно размещает root-owned помощник по пути `/usr/local/libexec/pi-aerial/system_deps` и узкое правило `/etc/sudoers.d/pi-aerial-system-deps`. Веб-обновление вправе вызвать **только** его команду `--ensure`: проверить и при необходимости установить отсутствующие пакеты из встроенного белого списка, без обновления всего дистрибутива и без передачи произвольных команд. Python-пакеты ставятся отдельно в `.venv` нового релиза. Если установку зависимостей не удалось завершить, новая версия не активируется.

Установщик спросит пароль веб-панели длиной не менее 12 символов и развернёт:

```text
~/pi-aerial/
├── current -> releases/0.2.1-g<commit>/
├── releases/<release>/.venv/       # отдельные Python-зависимости для каждого выпуска
├── data/
│   ├── videos/                     # вся видеотека на microSD
│   ├── modules/                    # модули, предыдущие версии
│   ├── github.json                 # только адрес репозитория и путь к deploy key
│   ├── settings.json
│   ├── admin_auth.json             # соль и хеш пароля
│   └── pending_update.json        # временный запрос обновления
├── update_helper.py               # независимый помощник обновлений
└── kiosk.sh                        # Chromium в полноэкранном режиме
```

Экран запустится автоматически на HDMI. Веб-панель: **`http://IP-МАЛИНКИ:8080/admin`**. Непосредственный экран: `http://127.0.0.1:8080`.

**Безопасность:** веб-панель использует пароль + CSRF, но работает по обычному HTTP. Подключайте Pi только к доверенной локальной сети. Никогда не пробрасывайте порт `8080` в интернет. Не используйте общий ключ с другими проектами: этот deploy key должен быть read-only и доступен только Pi-Aerial.

## 3. Обновления из GitHub через веб

Во вкладке **Обновления** нажмите **Проверить GitHub**. Панель сравнивает SHA установленного кода и `main` приватного репозитория. Если SHA отличается, доступна кнопка **Установить обновление**.

1. Авторизованный запрос ставит обновление в локальную очередь; веб-сервер не выполняет команды установки прямо из HTTP-обработчика.
2. Отдельная user-служба `pi-aerial-updater.path` запускает установленный помощник.
3. Помощник скачивает ровно `ouchZZZ/Pi-Aerial`, ветка `main`, через SSH read-only, сверяет SHA и создаёт каталог нового релиза.
4. Перед переключением root-owned помощник проверяет системные пакеты и автоматически доставляет отсутствующие. Если помощник ещё не установлен (старые установки 0.2.0), обновление продолжится без этой проверки, а в журнале появится предупреждение.
5. Новый релиз получает **собственное Python-окружение `.venv`**. Пакеты из `requirements.txt` устанавливаются заново при подготовке (включая повторную попытку после прерванного скачивания); зависимости старого релиза остаются нетронутыми.
6. Символическая ссылка `current` переключается атомарно. Проверяются `/api/health`, версия и точный Git SHA. При неудаче служба возвращается к прежней версии.
7. Если проверка успешна, обновляется и независимый helper (с сохранением предыдущего файла).

Настройки, видеозаписи, пароль и данные модулей лежат вне каталогов выпуска и **не удаляются при обновлениях**. Изменения `main` устанавливаются **только по нажатию кнопки**, а не автоматически. Если `main` изменился между проверкой и скачиванием, установка отменяется; повторите проверку.

Обновляться можно даже без изменения `VERSION`: учитывается SHA коммита. Для читаемого номера версии при выпуске полезно повышать `VERSION` (`0.2.1` и т. д.). Источник GitHub считается доверенным благодаря read-only SSH-доступу к единственному закреплённому репозиторию; это отдельный путь от подписи ZIP.

**Приватный репозиторий может оставаться приватным.** GitHub-токен не хранится в веб-панели.

### Обновление старой установки 0.2.0

Если Pi Aerial уже был установлен **до** появления автоматических apt-зависимостей, достаточно один раз обновить исходники и повторно запустить установщик (видеотека и настройки останутся нетронутыми):

```bash
cd "$HOME/Pi-Aerial"
GIT_SSH_COMMAND="ssh -i $HOME/.ssh/pi_aerial_github -o IdentitiesOnly=yes -o BatchMode=yes" git pull --ff-only
bash install.sh
```

Это установит root-owned помощник. Дальнейшие GitHub-обновления ядра не потребуют ручных действий с `apt`. При расширении системного белого списка новыми пакетами потребуется снова запустить `install.sh`, чтобы доверенная копия помощника была обновлена.

## 4. Каталог модулей

В репозитории каждая папка `catalog/<id>/` является модулем с собственными `manifest.json` и `index.html`, например `catalog/hello-widget/`. В панели: **Модули → Показать каталог → Установить / обновить**. Выключить или откатить модуль можно в той же вкладке. Защита: допустимые имена, ограничение размеров, запрет символических ссылок и вложенных директорий, запуск виджета внутри изолированного iframe.

При установке из GitHub используется проверенный SSH checkout. Отдельно остаётся возможность установки **локального подписанного ZIP**, для которой требуются публичные Ed25519 ключи в `~/pi-aerial/data/trusted_keys/` (см. `tools/make_signing_key.py` и `tools/sign_bundle.py`). Публичные ключи можно добавлять только локально; секретный ключ подписи храните вне Raspberry Pi.

## 5. Видео, погода, диагностика

Добавляйте ролики через вкладку **Видео** веб-панели. Рекомендуется MP4 1080p H.264 для Chromium. По умолчанию без видео показывается анимированный фон. Погода приходит из Open-Meteo примерно раз в 25 минут, без постоянного интернета остаются часы и видеозаставки; устаревший погодный кэш помечается.

Для настройки погоды в панели доступны город, координаты и часовой пояс IANA. По умолчанию — Саяногорск, `Asia/Krasnoyarsk`. Raspberry Pi 4 без внешнего RTC нуждается в NTP после отключения питания.

```bash
systemctl --user status pi-aerial.service pi-aerial-updater.path
journalctl --user -u pi-aerial.service -n 100 --no-pager
journalctl --user -u pi-aerial-updater.service -n 100 --no-pager
hostname -I
```

Отладка видео: `pgrep -af chromium`. Если ОС без рабочего стола (Lite) или не используется `labwc`, установленный автозапуск Chromium не сработает: нужна Desktop-версия Raspberry Pi OS с автовходом.

## 6. Разработка и тесты

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
pytest -q
bash -n install.sh && bash -n tools/system_deps.sh
python -m compileall -q app tools
```

Локальный запуск: `PI_AERIAL_BASE="$PWD" PI_AERIAL_DATA_DIR="$PWD/data" python -m uvicorn app.main:app --reload --port 8080`. Для задания пароля локально: `PI_AERIAL_DATA_DIR="$PWD/data" PYTHONPATH="$PWD" python tools/set_password.py`.

GitHub Actions (`.github/workflows/tests.yml`) запускает тесты на push и pull request. Для дальнейшей разработки лучше использовать PR и проверять CI перед слиянием в `main`: эта ветка служит источником обновлений работающей заставки.

## Известные ограничения

- Pi 4 поддерживает аппаратное декодирование HEVC, но реальная плавность 4K видео в Chromium с часами не гарантирована; начните с 1080p H.264.
- Автоматический откат срабатывает при неудачном запуске/проверке сервера, но не при любой логической ошибке отображения.
- Для установки обновлений и получения погоды нужен доступ к сети. Видеотека, интерфейс и часы работают локально.
- Приватный GitHub требует однократной настройки read-only deploy key на Pi.
- Тесты проверяют приложение на ПК; перед развёртыванием 24/7 проверьте терморежим и стабильность HDMI на самой Pi 4.
